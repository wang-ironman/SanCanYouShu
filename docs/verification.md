## 0.1.2：备菜合并、分类、完成清空与 AI 整理

2026-10-28，versionCode 3。修复备菜按单位拆成重复行、依赖原菜谱错误分类标签、缺少完成记录的问题。增加全选／取消全选、完成已选备货、从菜单恢复清单、手动调整名称分类，以及确认后应用 AI 整理。

确定性回归在旧版本返回 `tomato rows=3; fish is meat/seafood=false`，见 `artifacts/shopping-baseline.log`。同一回归在修复后返回 PASS，见 `artifacts/shopping-regression.log`。合并现在以规范食材名称为键，不把克数、个数和未知用量拆成独立食材行；无法换算的单位分别保留，不推测重量。分类使用食材名称规则，未知归其他，不再直接采用原菜谱的分类标签。

实际 API 35 模拟器验证使用两日专用菜谱夹具：

- 番茄、西红柿合并为一行 `100克 + 2个 + 待确认 1 处`；姜片与姜末合计为 7 克；故意标为调味干货的鲈鱼、鲜虾被重新归为肉蛋水产。清单共 5 项。
- 点击全选后显示已备 5/5，点击完成备货后进入空清单；强制停止、重启及切换页面后仍保持完成状态。
- 从当前菜单重新生成恢复 5 项，菜单与菜谱没有被删除。
- 只完成第一天后，全部视图只剩第二天的 3 项，姜为 2 克，第一天的番茄和鱼不再出现。
- 用本机模拟模型服务验证真实界面请求：AI 整理先显示预览；取消不写规则、不改清单；确认后名称规则保存并在重启后生效，原 `100克 + 2个 + 待确认1处` 用量未改变。该验证不代表真实模型的分类准确率。

完成记录针对具体食材需求保存，因此完成后不会因重绘、筛选、重启或仅调整名称分类而复活；换菜或改用量产生的新需求会重新列出。新菜单会生成新清单；也可明确恢复当前菜单的整份清单。

## 实际界面操作

使用最终 APK，在 API 35 模拟器完成：

1. 首页进入构建表单，填写 **3 天、4 人**，勾选早餐、午餐、晚餐。生成 9 个餐次，午晚餐各 2 道；实际私有目录中的 `plan.json` 与输入一致。
2. 进入备菜清单，显示合并食材及待确认项。勾选后计数从 0 增加到 1；强制停止应用并重新启动，**仍保留已备 1 项**。
3. 从早餐进入换菜列表，替换一道菜。持久菜单编号更新，备菜重新汇总（该夹具由 110 项变为 112 项），已备状态归零。
4. 在菜谱库通过表单创建测试菜谱，填写食材、数量、单位和步骤。确认应用私有文件保存的字段与输入一致；安装包升级后仍能保留。验证后已清理该测试夹具。
5. 实际查看首页、菜单及备菜清单截图；未发现文字重叠或按钮被应用底栏遮挡。运行日志未见应用崩溃。
